# NEVORA behaviour trends, October 2026

- **Cycle:** 1, discovery. Written 2026-10-17 by the UX Researcher.
- **Scope:** the whole product. Owners, managers and leads (mostly desktop), hourly employees (mostly phones) and the Clocker kiosk, on iOS and Android app stores, desktop web, mobile web and PWA.
- **Method:** 18 Mobbin screen searches (iOS and web), Apple HIG pages read from their published data with change-log dates, Nielsen Norman Group, Google and WebKit sources, two 21st.dev searches (search only), and the `ui-ux-pro-max` UX dataset. NEVORA today comes from `DESIGN.MD` (sections dated 2026-10-15 to 2026-10-17), the code, and screenshots in `.claude/evidence/`.
- **Limits:** Mobbin search covers iOS and web only, so Android evidence comes from Google's documentation and press. Baymard's relevant findings sit behind its paywall, so this report cites none. No new screenshots were taken, and nothing ran on a physical phone.

## 1. Summary

NEVORA already meets most of the screen-level patterns people expect: four tabs plus More on phones, a ⌘K finder on desktop, a swipe-down More sheet, swipe-to-decide in the Inbox, page-shaped skeletons, toasts, short motion with reduced-motion support, and a Today view for both audiences. The gaps sit around those screens, in how people sign in, how the app reaches them when it is closed, and how it adapts to their phone's settings. Employees type an employee ID and password while their bank and shopping apps use Face ID and passkeys. NEVORA ignores the phone's dark appearance and text-size setting, the first two things an App Store accessibility label asks about, and phones give managers no search. The top five moves are passkeys with biometric sign-in, a contextual notification prompt with an app-icon badge, text that follows the system text size, a search entry on phones, and a read-only offline copy of the employee's own schedule. Live Activities, widgets, haptics and dark mode should wait for the app-store wrapper and the legacy CSS clean-up, because building them in the PWA now costs more than they return. AI chat, voice clock-in, translucent "glass" chrome and attendance streaks look current, and each would cost trust in an app that handles pay.

## 3. Adopt and adapt

Draft scores use the 0–2 scale from `TEAM-RULES.md`, in this order: Usability, Familiarity, Trust, Accessibility, Brand, Durability, Cost, Continuity. The Product Designer sets the final scores.

### 3.1 Passkeys and Face ID / fingerprint sign-in (adopt)

**Evidence.** Shop and Klarna offer a passkey in one screen ([Shop](https://mobbin.com/screens/13ac7743-75b2-4322-ac82-10b338f25610), [Klarna](https://mobbin.com/screens/c9326fd7-2b6e-4c11-9719-e5c1c2b9973f)). Oura shows the iOS "Save a passkey?" sheet ([Oura](https://mobbin.com/screens/a2b2d537-fba1-424b-b3b4-7a031b907f2f)). PayPal leads with "Log In with Face ID" and keeps "Try another way" ([PayPal](https://mobbin.com/screens/aac8b496-1568-4ece-bb18-578ef25d7e99)). Affirm asks after the first passcode entry ([Affirm](https://mobbin.com/screens/22c759b5-f20a-4ff9-a545-05d06a8f65f8)). FIDO's Passkey Index (October 2025) reports a 93% sign-in success rate and 73% less sign-in time ([MobileIDWorld, Oct 2025](https://www.mobileidworld.com/fido-alliance-reports-3-billion-passkeys-in-use-shows-93-authentication-success-rate/)).

**NEVORA today.** Employee ID and password, with `autocomplete` set so password managers fill it (`src/app/login/page.tsx:49-66`). Forgot access and activation flows exist.

**Proposal.** After a successful password sign-in on a personal phone, offer "Sign in faster with Face ID next time" once, with "Not now". Keep employee ID and password as the fallback, and keep account recovery with the manager. The Clocker keeps its PIN, because a shared tablet must never hold a personal passkey.

| Platform | How it would feel |
|---|---|
| iOS app | System passkey sheet with Face ID; iCloud Keychain syncs it to the person's other Apple devices |
| Android app | Credential Manager sheet with fingerprint or face; Google Password Manager syncs it |
| Desktop web | Browser passkey prompt (Touch ID, Windows Hello) or "use a phone" QR code |
| Mobile web | Same system sheet as the app; the sign-in page offers passkey autofill on the ID field |
| PWA | Works in an installed web app. Standalone storage is separate from Safari, so the first sign-in in the PWA asks again |

**Risks.** It changes the authentication contract and needs a backend phase and Jose's approval. Shared family phones: the offer must say it saves to this device's owner. The sign-in pages keep their own blue palette until reviewed (`DESIGN.MD` Batch 2).

**Draft score:** 2 · 2 · 2 · 2 · 1 · 2 · 1 · 2 = **14/16**.

### 3.2 Notification permission in context, plus an app-icon badge (adopt)

**Evidence.** Cash App, Too Good To Go and Luma each explain which alerts you will get before the system prompt, and offer Skip ([Cash App](https://mobbin.com/screens/be5cd190-352d-4597-a544-31cb00eeea3a), [Too Good To Go](https://mobbin.com/screens/9d33d5b5-0ae2-47c5-9388-95004b16270f), [Luma](https://mobbin.com/screens/f8b9c208-0980-466d-a9f3-696fb4cd6876)). WebKit requires a user action before web push permission, and Home Screen web apps can set an icon badge once notifications are allowed ([WebKit, Web Push, Feb 2023](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/); [WebKit, Badging, 2023](https://webkit.org/blog/14112/badging-for-home-screen-web-apps/)). Safari 18.4 added Declarative Web Push for those apps ([WebKit, March 2025](https://webkit.org/blog/16574/digital-credentials-api/)). Apple's tab bar guidance reserves badges for critical information (HIG Tab bars, 2026-06-08).

**NEVORA today.** Push delivery through the service worker and a device setup page with install instructions (`src/components/portal-device-setup.tsx:27-33`). The bell shows a count on desktop (`.claude/evidence/errors/employee-home-1440.png`). U4 defers an Inbox tab badge.

**Proposal.** Ask at the moment the value is obvious: after an employee confirms their first schedule, show "Get told when your schedule changes or a request is answered", with the three alert types listed and "Not now". For managers, ask from the Inbox. Set the icon badge to the count of items that need this person (employee To do, manager Inbox), never to marketing.

| Platform | How it would feel |
|---|---|
| iOS app | Native permission sheet after the in-app explanation; badge on the app icon |
| Android app | Android 13+ runtime permission after the explanation; notification channels per alert type |
| Desktop web | Browser prompt only after a click on "Turn on"; no badge |
| Mobile web | No push in an iOS Safari tab. Show the install path first, which the device setup page already explains |
| PWA | Push and badge on iOS 16.4+ and Android once installed |

**Risks.** Permission fatigue if asked on first launch. A badge that counts things the person can't act on teaches them to ignore it.

**Draft score:** 2 · 2 · 2 · 2 · 1 · 2 · 2 · 2 = **15/16**.

### 3.3 Text that follows the phone's text size (adopt)

**Evidence.** Apple's App Store accessibility labels include "Larger Text", meaning text that grows to 200% or more ([Apple support 123073, 2025](https://support.apple.com/123073)). HIG Accessibility asks for at least 200% enlargement (updated 2025-06-09). The European Accessibility Act applies from 2025-06-28 to services such as e-commerce and banking, using WCAG 2.1 AA through EN 301 549 ([Global Policy Watch, June 2025](https://www.globalpolicywatch.com/2025/06/european-accessibility-act-june-2025-deadline-has-arrived/)). It doesn't name workforce software, so read it as the direction of travel, not a NEVORA obligation.

**NEVORA today.** 200% zoom and 400% reflow pass on 81 views (`DESIGN.MD` "Owed testing"). Type uses fixed `px` values, so a phone set to large text doesn't change NEVORA's text. The installed iOS PWA has no Safari text-size menu, which leaves pinch zoom as the only option (the viewport allows it: `src/app/layout.tsx:14-18`).

**Proposal.** Move the five type tokens and the phone floor (17/15px) to `rem`, and in the native shell map the OS text size onto the root font size. Test at the largest standard size and the first accessibility size: tab labels, Today strip figures, the next-shift pass and tables must wrap, never clip.

| Platform | How it would feel |
|---|---|
| iOS app | Text grows with Settings › Display & Text Size, as in Mail |
| Android app | Text grows with the system font size |
| Desktop web | No visible change; browser zoom and default font size keep working |
| Mobile web | Safari's "Aa" menu and Chrome's text scaling keep working |
| PWA | Layout ready; the OS setting reaches it only through the native shell |

**Risks.** Large text breaks dense rows (Timecards, Employees). U10 found that legacy rules out-rank component CSS, so the change has to run page by page with the computed-style baseline.

**Draft score:** 2 · 2 · 2 · 2 · 2 · 2 · 1 · 2 = **15/16**.

### 3.4 Search on phones for managers (adapt)

**Evidence.** HIG Search fields offers three placements: a search tab, a bottom toolbar, or inline (updated 2025-06-09, refined 2026-06-08). Messages and Copilot put search at the bottom ([Messages](https://mobbin.com/screens/b6ac40b2-f630-42e1-958e-4b9402b92151), [Copilot](https://mobbin.com/screens/cae80732-b155-48a3-85b9-be4eda2f3ad3)). Shopify's iOS app gives search its own button beside the tab bar ([Shopify](https://mobbin.com/screens/904d082d-43f9-44c5-b3ed-97d26af9bad2)), and Jobber puts Search in the tab bar for field crews ([Jobber](https://mobbin.com/screens/611f61f7-4a7e-4144-93c8-e095c0e8529f)).

**NEVORA today.** The ⌘K finder covers actions, pages, people and locations, but only from a desktop top-bar button (U8). On phones a manager finds a person through More › Employees and its filter.

**Proposal.** Keep the four tabs and More, as the constants require. Add a search button to the phone header for owners and managers that opens the same finder as a full-screen sheet with the field at the bottom above the keyboard, and list "Search" first in the More sheet. Recent people and actions show before typing; the empty query never lists the whole team (U8 rule).

| Platform | How it would feel |
|---|---|
| iOS app | Search button in the navigation bar, field above the keyboard; or the system search tab if the wrapper uses a native tab bar |
| Android app | Search icon in the top app bar opening a full-screen search view; Back closes it |
| Desktop web | No change; ⌘K and the top-bar button stay |
| Mobile web | Header button; field above the keyboard, sized 17px to stop iOS input zoom |
| PWA | Same as mobile web; reads the same authority-checked `/api/manager/finder` route |

**Risks.** Adding a fifth tab would break the four-plus-More structure; the header button avoids that. Offline: the finder must say "Search unavailable offline", never "No results" (U8 already reports failures as unavailable).

**Draft score:** 2 · 2 · 2 · 2 · 1 · 2 · 2 · 2 = **15/16**.

### 3.5 Pull to refresh in the installed app (adapt)

**Evidence.** iOS and Android list apps teach pull to refresh from Mail onward. Developers report that iOS Home Screen web apps lose the browser's pull to refresh ([DEV, iOS PWA design notes](https://dev.to/oskarlarsson/designing-native-like-progressive-web-apps-for-ios-510o); forum reports, not Apple documentation). The `ui-ux-pro-max` dataset flags accidental refresh and advises enabling it only where it helps.

**NEVORA today.** The manifest opens NEVORA standalone (`src/lib/notifications/manifest.ts:10`). Home has "Refresh home" and the Inbox has "Refresh" with an "Updated 10:30 AM" stamp (U2, U4). B4 polls Today every 30 seconds.

**Proposal.** Enable pull to refresh only in `display-mode: standalone` and in the native shell, on Home, Schedule, Inbox and Requests. Release past a threshold runs the same refresh the button runs and updates the "Updated" stamp. Keep the buttons for keyboard, screen-reader and switch users. In a browser tab, leave the browser's own refresh alone.

| Platform | How it would feel |
|---|---|
| iOS app | Native refresh control on scroll views |
| Android app | Material pull-to-refresh indicator |
| Desktop web | None; the Refresh button stays |
| Mobile web | The browser's own pull to refresh; NEVORA adds nothing |
| PWA | Custom pull with rubber-band resistance; static spinner under reduced motion |

**Risks.** Conflicts with the More sheet's swipe-down (`sheet-gestures.tsx`) and with the scrolling schedule grid; disable the pull while a sheet is open or a horizontal scroll is active.

**Draft score:** 2 · 2 · 2 · 2 · 1 · 2 · 1 · 2 = **14/16**.

### 3.6 A read-only offline copy of my own schedule (adapt)

**Evidence.** Qantas keeps its tab bar and tells you it couldn't update rather than blanking the screen ([Qantas](https://mobbin.com/screens/18f77caf-19d5-4199-98b4-a36f34096d23)); GoPay and HYPE show a calm retry ([GoPay](https://mobbin.com/screens/95483b32-a4d7-4025-b6e7-64220245eff5), [HYPE](https://mobbin.com/screens/e058ad1f-07de-4aed-8eac-7944bb0c2483)). Airline and ticket apps teach people that "my next trip" stays readable in a basement or on a plane.

**NEVORA today.** The service worker falls back to `public/fuel-portal-offline.html` ("You're offline") and caches no private data (`public/fuel-portal-sw.js:87-103`). The Inbox pauses offline and keeps no stale items (U4).

**Proposal.** For the signed-in employee only, keep their next 7 days of published shifts readable offline, stamped "Saved 7:31 AM. You're offline." Show no actions (claim, swap, confirm) while offline. Clear the copy on sign-out and on account switch. Never store pay, other people's data or manager views.

| Platform | How it would feel |
|---|---|
| iOS app | Schedule tab opens from the saved copy with an offline banner |
| Android app | Same; a snackbar offers retry when the connection returns |
| Desktop web | No change; managers on desktop are rarely offline |
| Mobile web | No offline copy in a browser tab, so shared and public phones keep nothing |
| PWA | The service worker serves the saved week to the installed app only |

**Risks.** Stale data looks like truth: a shift changed after the save. The stamp and a "may have changed" note handle this. Shared phones: store only in the installed app and clear on sign-out. This touches the service worker's privacy rule and needs Jose's approval.

**Draft score:** 2 · 2 · 1 · 2 · 1 · 2 · 1 · 2 = **13/16**.

### 3.7 Owner setup progress instead of a tour (adapt)

**Evidence.** Square shows "Complete your setup 50%" in the sidebar ([Square](https://mobbin.com/screens/9a32644d-c67c-4185-b2f3-f50af9ecf43a)); Klaviyo groups setup into completed cards ([Klaviyo](https://mobbin.com/screens/5ce9e545-398b-48f8-a051-b92fbe30d704)); HoneyBook lists steps with minutes per step ([HoneyBook](https://mobbin.com/screens/d345c7a0-0468-49fc-ad35-82b66fe1e7a5)). NN/g found that people who read a tutorial were no faster and rated tasks harder (5.49 vs 4.92 on ease) ([NN/g, 2020-03-08](https://www.nngroup.com/articles/mobile-tutorials/)).

**NEVORA today.** Setup items appear as "Setup needed" tasks on Home ("Availability deadline not set", "10 weekly hour targets missing") in `.claude/evidence/d3/home-1440.png`. U4 defers the owner setup checklist.

**Proposal.** Gather the existing setup tasks into one "Finish setting up" card at the top of the Owner's Home while any remain, showing "3 of 6 done" over the same 4px teal bar Home already uses. Each step links to the page that fixes it. The card disappears when done and leaves no tour behind. Employees keep no onboarding beyond activation.

| Platform | How it would feel |
|---|---|
| iOS app | Card at the top of Home; steps open full pages |
| Android app | Same |
| Desktop web | Card above Tasks; Owners set up mostly here |
| Mobile web | Card above the Today strip; long steps say "easier on a computer" |
| PWA | Same as mobile web |

**Risks.** It duplicates Home Tasks if both show the same item. Move setup items into the card and remove them from Tasks.

**Draft score:** 2 · 2 · 2 · 2 · 1 · 2 · 2 · 2 = **15/16**.

### 3.8 Plain-language questions in the finder (adapt, narrow)

**Evidence.** Aboard's HR assistant suggests questions such as "Who is out of office next week?" ([Aboard](https://mobbin.com/screens/5213a486-dd79-4c04-a769-e72674c736a4)). Asana and Shopify put an AI prompt on Home ([Asana](https://mobbin.com/screens/f2b651ef-bce1-464c-9c47-52f2fb187238), [Shopify web](https://mobbin.com/screens/c934c2ab-af86-4ebb-a44b-e91a22ae3bea)). Glassdoor labels its answers beta, cites sources and adds a "double-check" note ([Glassdoor](https://mobbin.com/screens/d68be235-0c3f-4ae8-a826-3f1a4c29d40c)). I found no confirmed 2026 AI-assistant launch from Homebase, Deputy, 7shifts or Connecteam in one search; the Market Strategist owns that question.

**NEVORA today.** No language model. Coverage help ranks candidates by rules (`src/components/coverage-assistant.tsx`).

**Proposal.** Teach the existing ⌘K finder a short list of manager questions in English and Puerto Rico Spanish: "who's off Friday", "who's clocked in", "open shifts this week", "quién está libre el sábado". Each one answers from an existing authority-checked read and opens the real page with filters applied. The finder offers no free-form chat, no generated text about pay or law, and never takes an action on its own. A generative model can come later, behind the same rule: every answer links to the record it came from.

| Platform | How it would feel |
|---|---|
| iOS app | The finder from 3.4; suggested questions show before typing |
| Android app | Same |
| Desktop web | ⌘K; suggestions under "Ask" |
| Mobile web | Header search button |
| PWA | Same; offline says "Questions need a connection" |

**Risks.** People will type questions the finder can't answer; reply "Try: who's off Friday" with the supported list. A wrong answer about who is working damages trust, so each answer shows its source and time.

**Draft score:** 2 · 1 · 2 · 2 · 1 · 2 · 1 · 2 = **13/16**.

### 3.9 Shift Live Activity, Live Update and a Next shift widget (adapt, native shell only)

**Evidence.** Swiggy, talabat and Waymo show progress on the lock screen ([Swiggy](https://mobbin.com/screens/b011ed21-a57f-4823-9b13-dbdc0b582183), [talabat](https://mobbin.com/screens/ec6b638f-ad1d-4f03-8b0e-889a969fdf28), [Waymo](https://mobbin.com/screens/bae9f53f-7fcb-462a-b391-4e290eea94ac)). HIG Live Activities (updated 2026-10-13) limits them to activities with a clear start and end that "don't exceed eight hours", and says to avoid sensitive information on the lock screen. Android 16 adds progress-centric Live Updates for the same job ([Android Authority, 2025](https://androidauthority.com/android-16-live-notifications-3518375)). Sweatcoin and Perplexity sell their widgets in-app ([Sweatcoin](https://mobbin.com/screens/36fdc175-debf-440c-b42e-bc9cdbf6f4c7), [Perplexity](https://mobbin.com/screens/9289eebd-4221-42df-9b55-82fef51780a4)).

**NEVORA today.** The employee next-shift pass with its countdown (U2) already holds the content. Web apps can't create Live Activities or widgets.

**Proposal.** Once Jose chooses a wrapper: a Live Activity from 60 minutes before a published shift to its end, showing start time and location only ("Main Office · starts 8:00 AM"), with no pay or hours totals. Clocking in stays on the Clocker; the activity shows the recorded status the Home card already shows. A small "Next shift" widget with the same two facts. Android manifest `shortcuts` (Request time off, My schedule) can ship in the PWA now at near-zero cost.

| Platform | How it would feel |
|---|---|
| iOS app | Lock screen and Dynamic Island; widget on Home Screen |
| Android app | Live Update chip in the status bar; Glance widget; long-press icon shortcuts |
| Desktop web | Not applicable |
| Mobile web | Not applicable |
| PWA | Icon shortcuts on Android only; nothing on iOS |

**Risks.** Shifts longer than 8 hours fall outside Apple's guidance; end the activity at the system limit and fall back to the Home card. Lock-screen content is visible to anyone nearby.

**Draft score:** 2 · 1 · 2 · 1 · 2 · 2 · 0 · 2 = **12/16**. Cost is 0 until a native shell exists.

### 3.10 Dark appearance that follows the system (adapt, after legacy CSS retirement)

**Evidence.** HIG Dark Mode: people "generally expect all apps" to respect their choice, and Apple advises against an app-only setting (updated 2024-08-06). Many apps still offer System, Light and Dark ([Fiverr](https://mobbin.com/screens/c829c27d-6085-4b77-8d87-a9af9e627f93), [Substack](https://mobbin.com/screens/0b20258f-630b-4a53-b2d2-5f9f022380c7)). "Dark Interface" is one of the App Store accessibility labels ([Apple support 123073](https://support.apple.com/123073)).

**NEVORA today.** No `prefers-color-scheme` rule in `src/`; `color-scheme: light` in `src/app/mobile-workforce.css:37`. U10 records 165 `!important` rules in `globals.css` and 38 legacy alias tokens. The B1 brand ladder (`src/lib/workspace-presentation/derive.ts`) derives light tokens only.

**Proposal.** Follow the system setting with no in-app switch at first. Build a dark token set for the `--g-*` layer and a dark branch of the B1 ladder that holds the same contrast floors. Start with employee phone pages once their legacy CSS is retired, then manager pages. The Clocker kiosk stays light, because it is a shared, bright-room device.

| Platform | How it would feel |
|---|---|
| iOS app | Follows Settings; status bar and `theme-color` switch with it |
| Android app | Follows the system dark theme |
| Desktop web | Follows the operating system |
| Mobile web | Follows the system; the manifest `theme_color` needs a dark value |
| PWA | Same; the offline page needs a dark version too |

**Risks.** A half-dark product looks broken, which is a trust problem. Payroll tables and the coral and amber status ladder need re-checking for contrast in dark. Company brand colours need a second set of floors.

**Draft score now:** 1 · 2 · 1 · 1 · 1 · 2 · 0 · 2 = **10/16** (does not pass). After legacy CSS retirement, Cost 1 and Trust 2 bring it to **12/16**.

## 4. Where NEVORA meets the bar, and the gaps inside it

- **Navigation.** Four tabs plus More for each role, one sidebar at 10 entries, breadcrumbs on desktop (U1, D1, D3). Matches the More pattern in [MyFitnessPal](https://mobbin.com/screens/19970f7d-4ed0-4afb-896b-899244d2f222) and [Jobber](https://mobbin.com/screens/611f61f7-4a7e-4144-93c8-e095c0e8529f). Apple warns that a More list hides content (HIG Tab bars); NEVORA's More holds low-frequency items, so this is fine.
- **Sheets.** Grabber, swipe-down and a visible Close match HIG Sheets and NN/g. **Gap to test:** NN/g says Back should close a sheet. The More sheet is a `popover="auto"` (`src/components/app-shell.tsx:266-268`), which Chromium on Android closes on Back. On iOS the standalone edge swipe goes back in history and may leave the page instead. I didn't verify either on a device.
- **Swipe.** The Inbox swipe meets the gesture rules: direction lock, threshold, snap back and visible buttons (U4, verified on the iOS simulator).
- **Loading and feedback.** Skeletons, toasts and pending labels match NN/g's thresholds and HIG Loading. INP replaced FID as a Core Web Vital on 2024-03-12, with 200ms as "good" ([web.dev](https://web.dev/blog/inp-cwv-launch)); no INP numbers are recorded for NEVORA yet.
- **Motion and delight.** Short, interruptible motion with full reduced-motion handling; celebrations are gated and never on payroll (U7).
- **Today.** The Today strip and the employee next-shift pass answer "what's happening now" first, as Uber Activity and Jobber do.
- **Android back.** Google turned on predictive back animations from Android 15 for apps that opt in, and extends them in Android 16 ([Android developers](https://developer.android.com/guide/navigation/predictive-back-gesture)). Any native shell must opt in and avoid swallowing Back.

## 5. Avoid

| Looks current | Why NEVORA should not do it |
|---|---|
| Translucent "glass" chrome copied onto web pages | Text over moving content loses contrast. U1 already had to raise the tab bar to 92% white to keep 4.5:1. Android users get none of it from their own system |
| Floating capsule tab bar drawn in CSS | It imitates iOS 26 on Android and the web, while Material 3 Expressive went shorter and flat. Use each system's own bar in the native shell |
| Open AI chat bubble or mascot | An answer about pay, hours or labour law that turns out wrong breaks trust in a payroll app. It also adds a second, unpredictable way to do what the finder already does |
| AI that publishes schedules or approves requests on its own | Approvals carry authority and revision checks (U4). A person must press the button |
| Streaks, badges or points for attendance | It turns lateness into a game and shames people. U7 excludes streaks |
| Full-swipe instant commit on approvals or pay | One accidental swipe would approve time off or a payroll step. Keep the half-row threshold and the pending state; never add swipe to payroll |
| Voice clock-in or face recognition at the Clocker | Shared tablets in noisy places; face data is biometric personal data that employees can't easily refuse. PIN plus bilingual labels already works |
| A custom voice screen | Keyboard dictation already works in every field in English and Spanish, with no new privacy questions |
| An in-app theme switch before dark mode is complete | Apple advises against app-only appearance settings, and a switch exposes the half-dark legacy pages |
| Onboarding carousels and coach marks | NN/g measured no gain and lower ease ratings. Familiar patterns do the teaching |
| Notification prompt on first launch, or marketing pushes | People deny the prompt before they see value, and promotions teach them to ignore schedule alerts |
| Pay amounts or hours totals on the lock screen | Apple's Live Activity guidance: avoid sensitive information on screens others can see |
| Infinite scroll on Timecards, Payroll or Employees | People lose their place in work they must finish; pagination and "Show all N" keep counts honest |
| Custom pull to refresh inside a mobile browser tab | The browser already does it, so the gesture would fire twice |
| Hyper-real 3D, heavy gradients, ultra-light type | `TEAM-RULES.md` names these as fads that erase the brand and lower contrast |

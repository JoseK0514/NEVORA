# Wave B inspection, round 1: interaction and states

Inspector: interaction and states (prefix IS-B). October 19, 2026. Preview from the newest `access.json` (fictional data), build `73c99cb` on `claude/p35-wave-b-808dfd`. Read only: no code, CSS, tests or data changed.

## Verdict

Not ready. The keyboard order and visible focus are sound on every page and control I reached, the role gates send people away cleanly, and most pending states disable the button and send exactly one request. But the page states have serious gaps. Insights throws away the whole report every ~15 seconds: the page shrinks from 7,716px to 1,138px, the scroll position jumps from 6,872 to 294 and focus drops to the body. On a phone, you can’t read the lower half of the report. That is a P0. Nine P1s follow: errors and failure messages that render off screen (Insights period error, Compose title error, Scheduling rules save failure, Payroll settings pending/failure feedback), a stale “Audience unavailable” error that stays beside a successful audience preview, Withdraw update and Remove coverage period firing with no confirmation, a failed Save template or Remove that replaces the whole page with “This page could not be loaded”, and the Scheduling rules jump links landing mid-section because their ids collide with the issue-focus prefixes. Fourteen P2s cover focus lost when a pressed button disables, missing pending labels, sign-out (401) shown as a permission change with no Sign in, a stray focus ring, and a few client validation gaps.

**Safety:** every non-GET was aborted, held or fulfilled locally by a Playwright route before any action was pressed. The one exception is `POST /api/reports`, the Insights *read*: its route handler only calls `readReports` (no writes), so it was allowed through. That read is the only way the page shows data. The audience preview (`POST …/communications/preview`) was answered locally with a fake `{state:"ready",count:3}` and never reached the server. CSV export was answered locally with a fake CSV. Status lookups that the UI makes as GETs (`…/communications/operations/<id>`, `/api/payroll/receipts`) were allowed. No POST, PUT, PATCH or DELETE reached the server, and Sign out was never pressed.

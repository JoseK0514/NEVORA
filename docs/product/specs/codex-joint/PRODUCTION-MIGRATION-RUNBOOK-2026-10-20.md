### Executor, transactions and unknown commits

No production executor or migration journal is established. Before Gate C, prepare and review an exact hashed executor invocation, per-file postconditions, external durable journal format and timeout/lock policy. This runbook is not a tested executor.

All application files except `0019_payroll_export_mappings.sql` and `0033_management_alert_preferences.sql` have outer BEGIN/COMMIT. For those two files the executor must issue explicit BEGIN, execute the unchanged full file, then COMMIT on the same connection; on any error roll back the open transaction and stop. PL/pgSQL BEGIN inside functions is not an outer transaction. Bounded static review found no transaction-incompatible commands; PG17 rehearsal remains required.

For embedded-transaction files preserve their own boundaries. This is one maintenance sequence with per-file atomicity, not a global atomic transaction. `psql --single-transaction` cannot override embedded COMMIT; an appended journal write is not atomic with that earlier commit. See [PostgreSQL psql transaction behavior](https://www.postgresql.org/docs/17/app-psql.html).

Use one persistent **direct, nonpooled PostgreSQL session** holding the agreed session advisory lock across the entire sequence. Set reviewed lock/statement timeout values based on rehearsal and log the backend/session identity. Separate psql subprocesses cannot inherit its lock. This lock coordinates migration operators only; it does not freeze application writers. See [Neon pooling limitations](https://neon.com/docs/connect/connection-pooling).

Use an external durable journal: operation ID, environment, candidate/manifest/executor hashes, order, full filename/hash, before-state evidence, start timestamp, outcome (COMMITTED/FAILED/UNKNOWN), and postcondition evidence. Durably record intent before execution and acknowledged result afterward; failure to persist journal evidence stops progress. No extra database journal DDL is authorized here.

On disconnect or lost acknowledgment, retain UNKNOWN even when the server may have committed. Freeze remains active. Reacquire the operator lock and reconcile catalog/data postconditions and journal against the last known checkpoint within already-approved least-privilege diagnostic access; read-only reconciliation in that scope proceeds without another permission stop. New or expanded credentials, roles or security-sensitive access require appropriate explicit authorization. Never replay from IF NOT EXISTS or automatically reconnect-and-continue writes. A reviewer must prove the committed prefix and verify a new reconciled continuation set; that review does not grant Jose's production authorization, which is required before write continuation. Unresolved state requires a recovery decision. Rehearsal must demonstrate failure before commit, commit-before-journal-ack loss, connection interruption, lock contention and both externally wrapped files. A future transactional journal adapter would be a separate reviewed/hash-pinned change, not a regex/semicolon rewrite assumed safe.

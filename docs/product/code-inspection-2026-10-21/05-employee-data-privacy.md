# Slice: Employee data, self-service & privacy (inspector report)

No critical/high; top items medium. 1-2 inferred from code, need load confirmation.

1. MEDIUM — Home's final coherence check fails open: last batch locks+re-reads indexes; any non-auth failure (55P03/57014/deadlock) marks only communications unavailable while other sections skip source_changed comparison but stay "complete" (employee-home.server.ts:207-225; header claims fail-closed). Fix: non-auth final-batch failure → all sections unavailable; inject-55P03 test.
2. MEDIUM — Employee READ paths take table-level SHARE locks on hot write tables: Home locks ~17 tables (employee-home.server.ts:204-207); employeeViewGuards LOCK employee_location_eligibility SHARE per guarded query (employee-profile.server.ts:31, dozens per Home load); Updates locks employees + FOR SHARE every row (communications/service.server.ts:73-76). Manager publish (ROW EXCLUSIVE) makes employee reads fail 1.5s lock_timeout right after the push lands; queued writer blocks later readers; alphabetical lock order vs writer order = deadlock risk (could abort a publish); logins (INSERT employee_sessions) and saveManagementAlertChoice conflict too. Fix: REPEATABLE READ snapshot or version fingerprints, or row-level FOR SHARE on specific rows; load-test concurrent publish + ~100 Home loads pre-release.
3. MEDIUM — Time-off reason unbounded server-side (requests/actions.ts:27 trim only; createTimeOffRequest no validation; client maxLength=250 only; no DB CHECK; 1MB action body) + listPendingTimeOffRequests no LIMIT selects reason + no overlap/duplicate/pending-count guard. Crafted Employee POST stores many multi-100KB reasons → inflates manager Home/dashboard/Inbox reads, pushes own notification list past 1MB MAX_BYTES and Home time-off index into failure. Fix: validate action+data layer (≤~250 chars, control-char reject), DB CHECK, pending cap, duplicate reject, LIMIT manager lists. [= Slice 7 #9, more severe mechanism]
4. MEDIUM — Create/Edit Shift pages serialize every employee's phone+email (incl. inactive) into RSC payload to client picker (schedule/new/page.tsx:132,146; edit/page.tsx:66,96; shift-assignment-fields.tsx client; listEmployees returns full Employee). Company-scope managers only, but picker needs id/name/role/positionIds/eligibleLocationIds/active. Fix: listAssignableEmployees projection without phone/email; RSC-prop test.
5. MEDIUM — Swap candidates expose coworkers' employee IDs (login identifier) + scheduleId in client payload (exchanges.ts:299-344 mapShift; swap/page.tsx:45-58; reviewed-swap-form.tsx). Login = ID+password, recovery = ID+email → all eligible-location employees can harvest usernames. Fix: presentational DTO; keep employeeId/scheduleId server-side.
6. MEDIUM — Employee ID: no format rule, no case-insensitive uniqueness; creation accepts Unicode/spaces (text(e.id,128).toUpperCase() only, employee-profile.server.ts:41,46); strict tenancy regex unused in live path; findEmployeeCredential upper(id)=upper($1) LIMIT 1 no ORDER BY → "SAM" vs legacy "sam" coexist, login arbitrary. Fix: EXISTS upper(id) reject in creation guard; ^[A-Z0-9][A-Z0-9._-]{0,127}$ for new; unique index on upper(id) after preflight; deterministic ORDER BY. [= DB slice #7]
7. LOW — Email validation inconsistent (profile /^[^@]+@[^@]+$/ vs recovery requires dot) → manager can save an email the employee can never recover with, 202 hides it; stored trimmed not lower-cased (uniqueness via lower(email) index only). Fix: one shared validator+normalizer. [= Slice 1 #6 overlap]
8. 9.

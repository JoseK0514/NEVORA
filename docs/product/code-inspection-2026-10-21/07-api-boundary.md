# Slice 7: API routes & server actions (inspector report; includes full route verdict table — see agent transcript for the table, key rows summarized here)

Context: no middleware/proxy/instrumentation — every handler guards itself. 58 api routes + manifest + push/open routes + 16 'use server' files audited. Verdict table: nearly all OK; exceptions below.

1. HIGH — Login: no throttle/lockout; unknown/inactive IDs skip scrypt (timing oracle). src/app/login/actions.ts:22-29. No limiter anywhere in repo; vercel.json none. Fix: per-ID+global attempt buckets (password_recovery_limits pattern), uniform response, dummy scrypt verify. [= Slice 1 #1/#3]
2. HIGH — Assisted recovery: any Company-scope Manager can take over another Manager (or any non-Owner) incl. payroll approvers. recovery.server.ts:42-56 (guard: target.role<>'OWNER' OR actor.role='OWNER'); raw proof returned to issuing Manager (route line 12) who redeems at /reset-access. Payroll REVIEW/APPROVE grants are per-Manager (native/scope.ts:8-19) → privilege escalation; actions appear as victim. Fix: Manager targets require OWNER actor, or target's role+scope+grants must be subset of actor's; deliver proof out-of-band to target's registered channel; notify target+Owners on issuance. [overlaps Slice 1 #5, adds escalation + proof-to-actor detail]
3. HIGH — Company-wide lock-heavy reads reachable by any authenticated user on every page render, no rate limit. operational-scope.server.ts:76-82,104 (FOR NO KEY UPDATE on singleton workspace + FOR UPDATE on actor) called from src/app/app/layout.tsx:54 on every /app render, open to all roles via scope-http.server.ts:12. payroll/store.ts:14-20,35-44 (LOCK TABLE employees SHARE ROW EXCLUSIVE; SELECT all employees FOR UPDATE; SHARE locks on time tables) used by SELF reads (/api/payroll/statements, documents via access.ts:27). Any employee can loop these endpoints and stall logins, manager reads, clock punches; payday load does it without an attacker. Fix: shared/key-share locks for read-only authority+statement reads; keep exclusive locks for writes; per-session rate limit.
4. MEDIUM — /api/payroll/documents/[id]/view ignores the pay-statements module toggle (sibling download route checks it at [id]/route.ts:23-27); module gate FAIL-OPEN: workspace-presentation/current.server.tsx:9-20 FALLBACK = all modules on, so a transient presentation read failure re-enables every gated API. Fix: add gate to view route; fail closed or explicit unknown for authorization-bearing gates.
5. MEDIUM — Public recovery buckets allow lockout of a named employee (4 requests) or all recovery (~300); counters increment pre-validation; no per-IP dimension. recovery.server.ts:19-20,31-33. [= Slice 1 #2] Fix: per-IP bucket; count per-account on successful issuance.
6. MEDIUM — Status-code taxonomy inconsistent: malformed JSON → 503 (period-close:31 [null body TypeError → "Outcome unconfirmed, retry" — invites blind retries], schedule-copy:26, clocker-recovery:10, account-recovery:11, action-center:10, reset-access:8); outages → 200 (management/profile:19, inbox-count:16); any failure → 401 (calendar/http.server.ts:33) or 403 (period-close/artifact:11,32); requireSessionMutationProof redirect swallowed → 503/unavailable (clocker-recovery; saveEmployeeCoreProfileAction; createEmployeeFormAction); 6 different error body shapes. Fix: validate body before try (400), map redirect→401, one error-shape helper.
7. MEDIUM — No server-side logging/error telemetry at all: zero console.* in src/app+src/lib (non-test), no instrumentation.ts, ~50 catch{...503} blocks discard errors. Operators can't investigate payroll/time incidents or spot abuse (F1/F2/F5). Fix: instrumentation.ts onRequestError + structured logger (route, request id, error class, SQLSTATE; never bodies/proofs/SQL).
8. LOW — CSRF/x-nevora-* conventions uneven: actor header required/optional/absent across write routes (absent on payroll POSTs incl. run approval, company-policies, workspace-presentation, reports, profile alerts); 3 Sec-Fetch-Site variants; push routes own origin logic; allowedOrigin falls back to request Host+X-Forwarded-Proto in production when FUEL_PORTAL_ORIGIN unset (clocker fails closed). Fix: one write wrapper (actor header + one Sec-Fetch policy); production fail closed without FUEL_PORTAL_ORIGIN.
9. LOW — Unbounded free text: time-off reason (requests/actions.ts:27; 0001:94 no CHECK), shift notes (schedule/actions.ts:58,187), callout reasonNote; server-action body default 1MB. Renders in manager lists/notifications/snapshots. Fix: action caps (500-2000 chars) + DB CHECKs.
10. LOW — No baseline security headers on /login and /app/* (next.config.ts only covers clocker/activation/portal paths): no frame-ancestors/XFO/CSP/Referrer-Policy/nosniff; login frameable (clickjack vs password-manager autofill). Fix: global headers() rule + CSP. [= Slice 1 #9]
11. LOW — Payroll: feature flag checked before auth (payroll/http.ts:55 enabled() before getSession → unauthenticated same-origin learns PAYROLL_DISABLED); /api/payroll/statements does getSession/moduleEnabled outside handle() try → default 500 bypasses JSON contract. Fix: auth first; move pre-checks inside guard.
12. LOW — Public assets: logo route serves any asset UUID incl. unsaved/superseded (public, immutable, not revocable; readLogoAsset doesn't check active logo); webmanifest = unauthenticated DB read per request, discloses theme+modules. Fix: serve only referenced assets / short TTL; edge-cache manifest.

CHECKED AND FINE: worker routes timingSafeEqual + ≥32-char secret; bounded fatal-UTF8 body reads; exact-key checks widespread; safeReturnTo strict allowlist; no stack/SQL/hash leakage; one-time secrets only where intentional (assisted proof, calendar URL on create, clocker enrollment code); no-store private + Vary: Cookie consistent; CSV formula guard; every /app page has its own guard; inert locator route no concrete risk.

SUMMARY: layer generally strong. Material: F1 login throttle, F2 Manager takeover via assisted recovery, F3 lock-heavy company reads. Then F4 module-gate bypass+fail-open, F6/F8 taxonomy, F7 zero logging.

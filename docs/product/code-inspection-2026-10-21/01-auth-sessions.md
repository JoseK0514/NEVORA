# Slice 1: Auth & sessions (inspector report, verbatim summary)

1. HIGH — No login throttling/lockout/backoff/concurrency cap. src/app/login/actions.ts:10-39; findEmployeeCredential (src/lib/data/employees.ts:81-116); no WAF rule in vercel.json. Short guessable IDs + 8-char minimum; each attempt runs scrypt on the 4-thread libuv pool (DoS). Recovery/activation have DB counters + scrypt cap; login has neither. Fix: failure-counted 15-min buckets by employee ID and IP; wrap verifyPassword in the admission.server.ts try-acquire cap; WAF rule for POST /login and /api/auth/*.
2. MEDIUM — Anonymous exhaustion of recovery/reset budgets. recovery.server.ts:32-33,19-20 (global 300 / per-employee 3 counted before validation), :66-71 (reset global 250 for any format-valid token). ~20 req/min stops all email recovery; ~17/min stops all resets incl. assisted codes; 4 requests lock one employee out of recovery. Fix: count issuance only when a matching active row issues a proof; count reset failures per token + per IP; keep global as flood ceiling excluding assisted codes; add exhaustion test.
3. MEDIUM — Login timing oracle (unknown/inactive IDs skip ~50ms scrypt). login/actions.ts:24-30. Fix: always verify against a fixed dummy hash.
4. MEDIUM — Dated KDF + policy. password.ts:7-16,18-51: scrypt N=16384 default, no params in encoding, no rehash-on-login; 8-char minimum only; no common-password list; no change-password flow; must_change_password (0001:44, employees.ts:104) never enforced. Fix: versioned encoding (N>=2^17), rehash on login, blocklist, enforce or drop the flag, change-password flow revoking other sessions.
5. MEDIUM — Assisted recovery: any company-scope MANAGER can issue a code for a peer MANAGER (only OWNER targets protected, recovery.server.ts:49); assisted issuance unlimited (:19-20 skipped when $4 non-null); attestation free text (:45); no notice to account owner on issue/completion (:88). Fix: MANAGER targets need OWNER actor; per-actor cap; "password was reset" email both moments.
6. LOW — Mail recipient handling: validRegisteredEmail allows , ; " (mail-transport.server.ts:3); maxRecipients:1 is not a nodemailer option (v10.0.16) so no cap; a stored `x,victim@evil.tld` can add recipients. Three disagreeing email validators (employee-profile.server.ts:26, recovery.server.ts:26, mail-transport:3). Fix: one strict validator; explicit envelope {from,to:[email]}; remove no-op option.
7. LOW — Session lifecycle: login never revokes prior session; expired rows never pruned; no per-employee cap; logout revocation budget 1s and PENDING ignored (copied token valid up to 14 days); 14-day absolute TTL, no idle timeout for OWNER/MANAGER. session.ts:12,28-54,56-66; logout.ts. Fix: delete prior token + bounded expired batch in createSession txn; alert on PENDING; shorter/sliding TTL for management.
8. LOW — Cookie hardening: plain `fuel_session`, no __Host- prefix; cookies().get silently picks one of duplicates (session.ts:47-53,70,120) while Phase F boundary rejects duplicates; literal name hard-coded in subscription-service.ts:177,199 and clocker setup route:16. Fix: shared readSessionToken() rejecting duplicates; __Host- with dual-read migration.
9. LOW — Headers: /login has no frame-ancestors/XFO/Referrer-Policy; /reset-access only frame-ancestors; /activate CSP has script-src 'unsafe-inline'; /app/** no frame protection (next.config.ts:18-41). Fix: global defaults + nonce CSP on auth pages.
10. LOW — Dead surface: retired activation action (src/app/activate/actions.ts; activateEmployeeCredential/getEmployeeActivationState employees.ts:165-194 no prod callers; unused passwordHash employees.ts:127,155); Phase F portal-credential-session.server.ts (341 lines, fs/pg/process.kill) + 4 helpers; portal-request.server.ts + /api/workspaces/[locator]/session route runs tenancy catalog queries for any well-formed cookie. Files hash-pinned in cloud-checks source-manifests (regenerate if pruned). Fix: move test-only files out of src/lib/auth, gate/delete route, delete retired functions.
11. LOW — Hygiene: double session read (getSession then proof) in several routes; getSession not memoized; assertManagementProof(proof, proof?.employee?.id) tautological at recovery.server.ts:44, invitations/service.server.ts:39, operational-scope.server.ts:64,77,102; adoption receipt UUID copied in 3 files. Mutations verified sound: no getSession-only mutation found.
12. LOW — Silent failures + test gaps: recovery.server.ts:40,:89 swallow SQL/SMTP errors; SMTP unset → silent 202; short password answered with "code expired" copy. Missing tests: createSession cookie attrs, session_login_changed, getSession expiry/inactive, reset-access route, wrong-password/inactive/rate-limit login cases, anonymous budget exhaustion.

HEALTH: invitation/recovery/reset engines well built (hashed 256-bit proofs, fragment tokens, config origin, single-use, returnTo allowlist, no fixation, deactivation revokes). Weak spots are the public edges (1,2,3,5) and dated KDF (4). Fix 1-3 and 5 first.

# 20 UI/UX Designer — Design system: component consistency

**Verdict.** On screen, the v3 Owner and Manager pages look consistent. Underneath, they are not built from one component set. The kit (`src/components/kit/kit.tsx`) defines the right primitives, but most screens bypass it. They use hand-written class names, or one of the three later "wave" dialects (`wave-a/parts.tsx`, `wave-b-forms.tsx`, `settings/wave-c-kit.tsx`). Page CSS then reshapes the kit per page with ID selectors and fake-ID specificity hacks. The fastest gains are one Button, one view switcher, one Sheet and one Status. After that, put the two v3 palettes into tokens and retire about 30 variant class families.

## Recommendations

1. **Collapse buttons into one kit `Button`: 3 kinds × 2 sizes, plus a plain kind.** Kinds: `primary` (fill), `secondary` (iOS grey fill on phone, white hairline on desktop, as now), `danger`, and `plain` (text-only: "Done", "Refresh", "Show 4 more"). Sizes: `regular` (50px phone / 36px desktop) and `compact` (30px visible, 44px hit built in: the mockup's `pill-btn` and `kbtn`). Add `icon` (square) and `block`. Retire, in v3 scope first: `cm-kbtn`, `cm-tc-kbtn`, `cm-tc-btn`, `cm-tc-done`, `cm-sheet__done`, `cm-refresh`, `cm-insights__button`, `pw-button`, legacy `.button primary/secondary/ghost/compact-button`. Leave `employeeButtonClass` for the Employee pass. *Why:* 10 heights are declared today. The 30px toolbar button exists twice (`schedule.css` `cm-kbtn` and `timecards.css` `cm-tc-kbtn`, same 30px/7px/#E2E2DF spec). The kit `<Button>` covers 10 of ~140 buttons, and `danger` is outside its type. The v3 Timecards still has a legacy `.button secondary/primary` batch-review branch (`timecards.tsx:435-444`; it even styles a `<select>` as a button). *Impact:* High. *Effort:* M. *Owner:* UI.

2. **Ship one `ViewSwitch` component for every "pick a view" control.** It renders an iOS segmented control on phones and underline tabs on desktop, with two contracts only: `links` (`aria-current="page"`) or `state` (`aria-pressed`). Counts are optional. If there are more than 4 options, use a pull-down menu instead of a sideways-scrolling chip row. Retire `cm-tc-seg`, `cm-tc-tabs`, `cm-insights__seg`, `.segmented.cm-locations`, `premium-inbox-filters`, `updates-filters`, Notifications `styles.filters`, `wc-pills`, `wa-chips`, `wa-segments`, `wc-segmented`, `section-tabs`. *Why:* 12 implementations with 3 ARIA contracts. `app-shell.tsx:129` lists 7 filter-row selectors just to scroll focus into view. Locations at 390 clips "Inactive" in a scrolling `wc-pills` row (QAOWNER-locations-390), while Team, a sibling page with the same layout, uses a segmented control (QAOWNER-team-390). Spec contract rule 6: "One row, one filter row." *Impact:* High. *Effort:* M. *Owner:* UI.

3. **Unify sheets and dialogs into one `Sheet` (native `<dialog>`) with three presentations.** `sheet` is the phone bottom sheet: grabber, title, and "Done" top-right as a `plain` button; swipe-down is wired whenever a grabber shows. `dialog` is a centred confirm or editor with a "Cancel" button, not an X icon. `popover` is for menus. On desktop, `sheet` becomes the side pane or a centred dialog. Retire `cm-sheet`, `cm-tc-sheet`, `wc-dialog` and the X-icon close. *Why:* the Inbox item sheet draws a grabber (`manager-inbox.tsx:525`) but has no drag handling. Only the More sheet uses `SheetGestures`. iOS users will try to swipe it down and nothing happens: a false affordance. Timecards' sheet has no grabber, Clocker's dialogs use an X (`clocker-break-types.tsx:180`) and Inbox's uses "Done". Three close patterns for one job. *Impact:* High. *Effort:* M. *Owner:* UI.

4. **One `Status`, 4 tones, 2 forms. Remove the filled pills from Shift requests now.** Tones: neutral, review, done, urgent. Forms: `glyph` (glyph + word, for lists) and `text` (word only, for table cells, as the Timecards mockup shows). Notices may add `info`. Retire `StatusPill` / `.status-pill`, `cm-tc-status`, `wc-tag`, `task-tag`, and map `error/success/warning/saved/conflict/attention/dark` onto the ladder. *Why:* `exchange/page.tsx:266,281` still renders legacy `.status-pill` with soft-green and soft-amber fills on a v3 page (Shift requests > Team activity). The clean CSS never restyles `.status-pill`, and the spec lists "pills on every row" as banned. Right now 13 tone names are in use. *Impact:* Medium-High. *Effort:* S. *Owner:* UI.

5. **Give `Card` explicit variants and delete the per-page ID overrides.** Use `grouped` on phones: an iOS inset list with a footnote-style header *outside* the box, plus an optional footer. Use `panel` on desktop: a hairline box with its head inside. Move Team ("Find people", "Employees"), Settings, Locations and Insights' "RECORDED TIME" onto `grouped`. On phones, put search under the large title instead of in a "Find …" card. *Why:* the same `<Card>` renders three header styles today. Inbox and Insights get the iOS header only through ID-scoped CSS (`insights.css:81-98`, `#report-people > .nv-card__head`). Team, Settings and Locations keep bold in-card titles (compare QAOWNER-inbox-390 with QAOWNER-team-390 and QAOWNER-settings-390). Spec: "inset grouped lists". *Impact:* Medium. *Effort:* M. *Owner:* UI.

6. **Extend `Row` and migrate the bespoke rows.** Add `disclosure: "navigate" | "expand" | "none"`, a right-aligned tabular `value`, and an inline `action` slot (Schedule's "Find cover" / "Plan" compact buttons). Then move `inbox-row`, `premium-timeoff-row`, `manager-floor-row`, `home-recent-row`, `attendance-review-row`, `manager-correction-row`, `profile-setting-row` and the 19 files with raw `nv-row` markup onto `<Row>`. *Why:* Inbox hand-builds expand rows because `Row` (`kit.tsx:189`) only knows the chevron-right link. Every raw copy restates the structure that QA keeps patching (wrapping, 44px hits, separators). *Impact:* Medium. *Effort:* M. *Owner:* UI.

7. **Merge the wave duplicates into the kit:** one `Notice` that always announces itself (alert/status, with `quiet` to opt out), one `Fact`/`Facts`, one `EmptyState`, one `ActionForm` (single failure UI and single confirm step). Then delete `wave-c-kit`'s copies and `page-header.tsx`, which is only imported by tests, and fold `Masthead` into `PageBand`. *Why:* there are two `Notice` contracts today. `wave-a/parts.tsx:22` sets the role itself; `wave-c-kit.tsx:42` relies on each caller wrapping it (`wave-c-form.tsx:225`, `brand-editor.tsx:212`), so a new caller can easily ship a silent result. There are also two EmptyStates and two ActionForms with different error styles (`wave-a/action-form.tsx` vs `wave-b-forms.tsx:53`). *Impact:* Medium. *Effort:* S. *Owner:* UI.

8. **Put both v3 palettes into tokens, then decide on company branding.** Name the desktop "warm" set alongside the iOS set: e.g. `--cm-d-label-2: #6B6B68`, `--cm-d-hair: #ECECEA`, `--cm-d-fill`, plus one teal, one red, one amber. *Why:* the 6 clean files hold 446 hex literals. #6B6B68 alone appears 76 times. There are three teals (#087571 tint, #0B6B67 desktop primary, #076A66 secondary text), four reds (#D70015, #D92D20, #B42318, #FF3B30) and two ambers (#A05A00, #93500A). The mockup itself mixes them (`v3.css:7` vs `:132`). *Product question:* the clean layer pins `--nv-accent` to #087571 (`premium-clean-manager.css:15`) and never reads `--g-accent`. As a result, Settings > Branding "Company color" no longer tints Owner and Manager pages. Decide whether that is intended. *Impact:* Medium. *Effort:* M. *Owner:* UI (tokens), Product (branding).

9. **Replace the specificity war with `@layer` (`legacy, kit, clean, page`).** Then drop the 120-character prefix and the fake-ID hacks. Put the 44px hit area inside `Button` (compact) and `Row`, not in per-page `::after` patches. *Why:* there are 1,412 prefixed lines and 304 `:not(#nv-kit|#cm-*)` hacks. The file header admits the prefix is long "on purpose" so it can beat the shared premium layers (`premium-clean-manager.css:4`). There are 23 separate `::after` hit patches. Every new page must out-shout four older layers (`portal-premium.css` 2.1k lines, `premium-wave-a/b/c.css`), and that cost is why variants keep multiplying. Do it after items 1–7 have shrunk the surface. *Impact:* Medium (it is what makes the rest stick). *Effort:* L. *Owner:* UI.

10. **One `PageFoot` (freshness + Refresh) and one `Footnote`.** Retire the 8 refresh affordances (`cm-refresh`, `manager-live-refresh`, `attendance-review-refresh`, `updates-refresh`, `styles.refresh`, `styles.refreshButton`, `employee-time-refresh`, `profile-refresh-link`) and the 7 note classes (`wb-note`, `wa-card-note`, `styles.note`, `premium-note`, `wc-footnote`, `updates-footnote`, `cm-section-foot`). *Why:* Inbox, Insights and Timecards all end in a "time · Refresh" line built three ways (QAOWNER-inbox-390, -insights-390, -timecards-1440), and Settings and Locations use yet another icon-note footer. While migrating, fix button copy case: "Find Cover" → "Find cover" (QAOWNER-schedule-390). *Impact:* Low. *Effort:* S. *Owner:* UI.

### Minimal component set (target)
`PageBand` · `ViewSwitch` · `Card(grouped|panel)` · `Rows/Row(disclosure, value, action)` · `Status(glyph|text)` · `Notice` · `EmptyState` · `Button(primary|secondary|danger|plain × regular|compact, icon, block)` · `Sheet(sheet|dialog|popover)` · `ActionForm` · `Field/FieldPair/FormActions` · `ActionBar` · `StatGrid` · `Avatar/Tile` · `PageFoot/Footnote` · `Money/Duration`. That is about 16 primitives, against the roughly 45 class families in use today.

## What's good
- The kit API is well designed: `Row`'s status slot, `Button`'s `blockedReason` (a disabled button that always says why), `Status` as glyph + word, and `MetaParts` (no orphan "·"). The base is right. It just isn't used consistently.
- The v3 screens have one visual voice across Inbox, Schedule, Time off, Insights and Timecards. Segmented controls, grey/teal decision buttons and the iOS grouped headers match the mockups.
- Accessibility intent shows in every variant (labels, `aria-pressed`/`aria-current`, 44px hit areas, reduced-motion checks), so consolidation can keep the behaviour while removing the duplication.

## Not checked / limits
- No browser was used (my brief did not allow it). Findings come from code and the provided screenshots, so the rendered heights are what the CSS declares, not measured values.
- I did not audit the Employee and Lead dialect (`employee-*`, `employeeButtonClass`, `mobile-workforce.css`) beyond counting it. It is outside v3 and should be a separate pass.
- I did not check dark mode or large-text behaviour of the variants, and did not check whether legacy branches in dual-render files (e.g. `timecards.tsx` CSS-module path) are still reachable for Owner and Manager.
- The usage counts come from grep. A few dynamic class names (template strings) may be under-counted.

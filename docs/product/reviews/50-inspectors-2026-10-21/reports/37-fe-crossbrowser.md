# 37 Cross-browser QA Engineer — Chromium vs WebKit vs Firefox, Owner and Manager at 390 and 1440

**Verdict.** On current engines (Chromium 153, Firefox 155, WebKit 26.6) the Owner and Manager app works the same in all three. Every menu, sheet and dialog I opened landed in the same place, there were no hydration warnings and no horizontal overflow. There are two real problems for engines that are one or two years old. First, the app shell checks popover state with the `:popover-open` selector in JavaScript, which Safari 16 does not support. When I simulated Safari 16, **every Owner, Manager and Employee page showed "This page could not be loaded"**, and Safari 16.4 is inside Next 16's default browser targets. Second, the fade on the segmented tracks breaks in every engine without scroll-driven animations: the left edge is faded all the time, and the "more to the right" cue is missing. That covers Firefox today and Safari 17–18.

## Recommendations

1. **Stop the app shell crashing on Safari 16: guard every `:popover-open` check in JavaScript.** Add one helper, for example `isPopoverOpen(el)`, that returns false when `'showPopover' in HTMLElement.prototype` is false, or wraps `matches()` in try/catch. Use it at `src/components/app-shell.tsx:126` and `:166`, `action-menu.tsx:50` and `:90`, `manager-issue-focus.tsx:19` and `portal-device-setup.tsx:80`. Also make `sheet-gestures.tsx:11` (`SHEET_SELECTOR = "[popover]:popover-open"`, used in a global pointerdown handler) safe; otherwise it throws on every tap. `reports.tsx:67` already uses try/catch and is the model to copy.
   *Why:* I simulated the JavaScript side of Safari 16 in WebKit: no Popover API, and `:popover-open` treated as an invalid selector. Manager `/app`, `/app/inbox` and `/app/schedule` at 390, Owner `/app/settings` at 1440 and Employee `/app` at 390 all rendered the error screen. The console showed "SyntaxError: ':popover-open' is not a valid selector … in the `<AppShell>` component … handled by `<ErrorBoundaryHandler>`" (screenshot `scratchpad/xb/shots/ios16sim-webkit-QAOWNER-_app_settings-1440.png`). A control run without the simulation loaded normally. The `[pathname]` effect at `app-shell.tsx:164-167` runs on every mount, so the crash is certain wherever `#manager-more-navigation` or `#employee-more-navigation` exists. Affected devices: iPhone 8, 8 Plus and X, which cannot go past iOS 16, iPhones whose owners stayed on iOS 16, and Macs capped at Safari 16 (Big Sur).
   *Impact:* High. *Effort:* S. *Owner:* UI.

2. **Decide the supported-browser floor, write it down, and handle anything below it on purpose.** `package.json` has no `browserslist`, so Next 16 targets its default, which includes Safari 16.4. Yet the menus (the More sheet, account menu, schedule More, Insights menus and device settings) depend completely on the Popover API, which arrived in Safari 17.0. Either add a popover polyfill such as `@oddbird/popover-polyfill` so iOS 16 still gets working menus, or raise the floor to Safari/iOS 17 and show a clear "update your browser" page instead of a crash. Then add a legacy-Safari smoke test to CI using the same init-script simulation I used (`scratchpad/xb/ios16b.mjs`).
   *Why:* even after #1, the More tab would do nothing on iOS 16. No author CSS hides `[popover]` without the UA rule, and `popoverTarget` is a no-op there.
   *Impact:* High. *Effort:* M. *Owner:* Product (Jose) chooses the floor, UI implements.

3. **Fix the segmented-track fade on engines without scroll-driven animations.** Move `animation: cm-track-fade …; animation-timeline: scroll(self inline)` inside `@supports (animation-timeline: scroll())` at `premium-clean-manager.css:847`, `:852` and `:1089`.
   *Why:* without a scroll timeline, the shorthand becomes a 0s animation with `fill: both`, so the **100% keyframe stays on permanently**. In Firefox 155 the computed `mask-image` is `linear-gradient(to right, transparent, #000 24px)` on every track at both 390 and 1440. That covers Inbox, Time off, Team, Notifications, Updates, Shift requests, Person, Availability and Locations (`scratchpad/xb/sweep-firefox.json`). On those pages the left edge of the track and of the selected "All" or "Everyone" segment is faded (`shots/big-firefox-inbox-track-390.png` against `big-chromium-…`). On tracks that overflow (Availability at 502/326px, Locations at 343/318px) the right-edge "more" fade is missing, so the 4th and later segments are not hinted (`big-firefox-avail-track-390.png` against `big-webkit-…`). The `@supports not` fallback at `:1049` never wins, because animation values override normal declarations. Safari only gained scroll-driven animations in 26, so iOS and macOS Safari 17–18 users get the same bug. That is still a meaningful share of iPhones.
   *Impact:* Medium. *Effort:* S. *Owner:* UI.

4. **Return focus to the trigger when a menu or sheet closes in Safari.** In WebKit, after Escape on the phone More sheet, the schedule More menu or the account menu, focus went to `<body>`. Chromium and Firefox put it back on the "More" or account trigger (`scratchpad/xb` interaction log). The cause is that Safari does not focus a button when it is clicked, so the popover has nothing to return to. Record the trigger in `beforetoggle` (`action-menu.tsx`) and focus it on close when focus is in the menu or on body.
   *Impact:* Low–Medium (keyboard and switch users on Mac Safari). *Effort:* S. *Owner:* UI.

5. **Insights menus without anchor positioning (desktop Safari 17–18): position them with JavaScript instead of a bottom sheet.** `clean-manager/insights.css:39-43` turns the Period and Export menus into a bottom-centred sheet. At 1440 that puts the menu about 800px from its top-bar trigger. `actionMenuGeometry` already exists, so reuse it at 761px and wider and keep the sheet for phones. On current engines the anchoring is identical across all three: Period menu at x688/y47 and Export at x676–677/y47.
   *Impact:* Low. *Effort:* S. *Owner:* UI.

6. **Don't hard-code text-line offsets; test Windows and Android system fonts.** The v3 stack (`premium-clean-manager.css:8`) gives SF on Apple devices, Segoe UI on Windows and Roboto on Android. Yet the sticky offsets for Payroll's tabs assume an exact line count: `premium-clean-manager.css` has `top: calc(28px + 4px + 1.875rem + 8px + 1.25rem + 16px)` for "summary takes one line" and a separate 2.5rem version for 761–999px. Different fonts wrap differently, and the tabs will then overlap or gap. Measure the band height (ResizeObserver already sets `--cm-*-h`) or let the tabs flow after the band. Add one Windows-Chrome or Edge run and one Android-Chrome run to QA.
   *Impact:* Medium (owners often use Windows PCs). *Effort:* M. *Owner:* UI.

7. **Add Firefox and a "previous Safari" profile to the standing QA sweep.** Earlier QA rounds ran WebKit layout passes (`qa-out/final2-mgr-desk/layout/webkit`) but almost nothing in Firefox, and Playwright's WebKit is Safari 26.6, so it cannot show Safari 16–18 gaps. Both #1 and #3 slipped through for that reason. A 46-page Firefox sweep takes about 2 minutes (`scratchpad/xb/sweep.mjs`).
   *Impact:* Medium. *Effort:* S. *Owner:* UI.

8. **Ignore aborted fetches when someone leaves a page.** In WebKit only, leaving a page while data is still loading raised uncaught "Fetch API cannot load …/api/manager/today | /api/manager/action-center | /api/notifications | /api/reports due to access control checks". Chromium and Firefox raised none. Treat `AbortError` and navigation rejections as quiet so Safari users don't fill the error monitor and don't see an error state flash before the next page.
   *Impact:* Low. *Effort:* S. *Owner:* UI.

## What's good
- Every interaction I tested matches across engines to the pixel: the phone More sheet (0,96,390×748, focus moves in, Escape closes), the Inbox item sheet (`dialog.cm-sheet` at y479, h365, focus on its title), the Timecards sheet, schedule More on phone and desktop, the account menu, the ⌘K command finder dialog, and both Insights menus.
- 46 page loads per engine (Owner's 19 pages plus Manager's 4, at 390 and 1440) showed no horizontal scroll, no hydration warnings and no height differences caused by the engine. The height differences that did appear were loading-state timing.
- Progressive enhancement is mostly done right. Anchor positioning and the scrolled-header edge sit behind `@supports`, `backdrop-filter` has its `-webkit-` prefix, the tracks have `::-webkit-scrollbar` fallbacks, and CSS nesting is flattened in the served CSS (0 `&`). `:has()`, container queries and `dvh` are all within Safari 16 support.

## Not checked / limits
- **No real devices.** Playwright's WebKit is Safari 26.6. The iOS 16 crash comes from a JavaScript simulation: Popover API removed and `:popover-open` thrown as an invalid selector. The CSS side of Safari 16 was not simulated. The Safari 17–18 track bug is inferred from Firefox, which has the same missing feature (`CSS.supports("animation-timeline: scroll()")` is false).
- Playwright's Firefox has no mobile or touch emulation, so `(pointer: coarse)` rules were not exercised in Firefox at 390. Firefox for Android was not covered.
- Windows and Android fonts were not rendered; this is a macOS host.
- The preview returns 404 for `/fonts/typeface/inter/variable.woff2`: the preview copy lacks the file, although it is tracked in git. All engines fell back to the TTF, and Firefox logged "downloadable font: download failed". This is not a product bug, but font rendering in the preview is not exactly production.
- In the Chromium run, Updates and Shift requests at 390 returned transient 500/503 from the dev server. Firefox and WebKit loaded them fine, so I treated this as server flakiness, not an engine difference.
- Not tested: swipe-to-close gestures, background scroll under modal dialogs on iOS, iOS date and time picker behaviour, reduced motion across engines, the Spanish locale, and Lead and Employee pages beyond the crash check.
- Evidence: `scratchpad/xb/` (`sweep-{chromium,firefox,webkit}.json`, `inter.mjs` log, `ios16b.mjs`, `shots/`).

## Findings

- **ISSUE P2 — WebKit pointer-opened generic sheets lose the opener on close.** Fresh Home → View today’s shift → Done or Escape; Schedule → first shift → Done or Escape; Requests → New request → Escape; More → Availability → Escape all leave `document.activeElement` at BODY. All six exact-opener comparisons pass in Chromium/Firefox. This is an interaction/accessibility defect; browser WebKit evidence is not physical Safari certification. Prototype AGENTS requires exact opener return including Safari pointer activation. Generic Modal relies on native close without storing an opener (`src/App.tsx:40–60`). Evidence: `webkit-results.json`, six `webkit-focus-*.png`, `webkit-trace.zip`.
- **ISSUE P2 — Escape discards the owned unsent time-off draft.** New request → dates Nov 12–13 → note “Independent QA draft” → Escape → New request returns all three fields empty, without a prompt, in all engines. This is source parity as well as recovery UX: frozen source `src/app/app/requests/time-off-signature.tsx:17–48` retains an owner-bound unsent draft. Prototype `TimeOffRequest.tsx` holds values only in the unmounted component. Evidence: each engine’s `draft-escape` result/capture/trace and `source-contract.txt`.
- **ISSUE P2 — Notification navigation highlights the wrong owner.** Home → bell opens Notifications but marks More current in all engines. Frozen `src/lib/navigation.ts:197–198` explicitly places Employee Notifications under Home. Prototype `App.tsx:197` maps notifications to More. Evidence: all `notification-nav` cases and source excerpt.
- **ISSUE P2 — Partial-read messaging is inconsistent with immediate success.** With supported `state=partial`, Schedule → Review this week → Confirm schedule review reaches “Schedule reviewed”; Requests → New request → Nov 12 → Review → Submit reaches “Request submitted”. Both retain “Some information could not be checked. Refresh before relying on these details.” All engines reproduce actual receipts, not merely enabled buttons. This is a UI trust/recovery concern. The fixture does not identify exactly which read failed; it is **not evidence of revoked authority or a P1 security bypass**. Source uses actual session/mutation proof rather than this query fixture. Evidence: all `partial-schedule` / `partial-timeoff` captures, results and traces.
- **ISSUE P3 — Prototype breadth remains bounded.** Schedule exposes Oct 26–Nov 1, Nov 2–8, Nov 9–15 and disables Next at the third week; initial Previous is source-disabled. Hours → Timecards renders the explicit empty history message. These are limited fixtures, not evidence that production loses records. Source supports real week selection; prototype `Hours.tsx:46` passes no history and `Timecards.tsx:11` defaults history to `[]`. No populated history journey is reachable in this inspected wiring. Evidence: all `schedule-breadth` / `timecard-history` cases and source excerpts.
- **RISK P1 integration gate — Time-off module authority is not represented by the generic request model.** Frozen application `requests/page.tsx:46` gates `timeOff`; `requests/actions.ts:23–25` requires self-service, enabled module and mutation proof. Prototype Requests mounts New request without an equivalent modeled time-off capability. No undocumented query parameter was treated as a supported feature flag. This is unmodeled authorization behavior to preserve during integration, not a reproduced deployed bypass. A live module-off/expired-proof denial test is a prerequisite to integration approval and was prohibited in this audit.
- **VERIFIED — Local sign-out closes private navigation and refuses direct Pay re-entry.** Profile → Sign out → confirm; then same-tab `?page=pay&pay=enabled` stays Signed out with no navigation in all engines. This proves only the local demo-session fence. Evidence: all `signout` and `signedout-pay` results/screenshots/traces.

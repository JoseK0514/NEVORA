# Employee mobile Passkeys design record

Passkeys extends the incumbent Employee mobile system through **Your account → Security → Passkeys**. It preserves the selected corporate teal direction, system font stack, official wordmark and Phosphor regular symbols. The existing 23 Light color roles and 20 Dark overrides remain unchanged. Passkeys CSS consumes their semantic roles for surfaces, text, actions, dividers, feedback and removal; it introduces no palette, font or icon family.

The screen uses the existing Heading, Section, Button and Icon primitives. Related passkeys share one divided list rather than nested cards. Metadata wraps, with Remove able to move below the text. Cards retain 16px corners, controls 12px, compact details 8px and sheets 24px. Spacing comes from the established 4/8/12/16/20/24/32px scale; primary actions retain 48px minimum height and compact actions 44px. The teal introduction and full-width setup action apply existing components to this account task without establishing a new visual rule.

Setup and removal reuse the native dialog sheet, keyboard containment, Escape and opener restoration. Removal names the chosen key and initially focuses Keep. Help reuses Disclosure’s native details/summary and Phosphor caret. Unconfirmed changes focus and reveal the recovery heading; forward Tab explicitly reaches Refresh, including WebKit. Refresh wording describes checking the saved list without assuming setup or removal succeeded.

The frozen desktop boundary at development `46e202786863279302026ee03a0e225c359fa55c` supports the own-account list’s name, added and last-used metadata, supported-browser setup and confirmed removal, including the last key. This mobile prototype makes these operations explicitly fictional. Feature-off hides the account entry; refusal, loading, failed-read and unknown-result states withhold trusted records or changes. Unsupported browsers retain own-key management while withholding setup. Unknown results require refresh before another change. There is no rename, coworker/admin control or biometric editor, and no real native credential prompt, browser permission or authentication mutation.

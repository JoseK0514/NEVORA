## Server checks (all in `readScopedEmployeeSummary`, `src/lib/company-access/operational-read.server.ts`)
1. Runs through the shared protected read (`read()`): the current operational authority must be ready; the role must be
   Owner or Manager; the session must have a scope; the result crosses the final guard transaction (workspace read guard,
   the actor's row `FOR SHARE`, `operationalScopeStatements` for the actor's exact location scope and authority), and the
   authority is re-read and must be unchanged and fresh, else `source_changed`.
2. Refuses an invalid employee id.
3. Refuses a company-wide view (`ctx.ids===null`): Owners and company-wide Managers keep the full profile read.
4. Refuses anyone not on the scoped Team roster (`roster(ctx, ctx.ids)`, the same SQL as the scoped Team list): the person
   must be active, their home location in this workspace, and their home or an eligible location among the Manager's.
   Another location's person, an inactive person and another company's person (an unknown id here: one workspace per
   database) are refused with `access_denied`.
5. Returns only the roster row (id, first and last name, role, the person's locations within the scope, filtered in SQL)
   and those locations' minimal fields (id, name, short name, active): the scoped Team list's data, nothing more.

The page asks this read only when the company-wide read has refused a Manager. Hours come from the existing scoped
`readOperationalEmployeeHours` (unchanged). The edit sheets and Access and sign-in show the company-wide closed state
without reading the person; the subpages (pay, time off, restrictions, Clocker PIN) are unchanged and stay company-only.

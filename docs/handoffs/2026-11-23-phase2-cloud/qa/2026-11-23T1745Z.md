## Findings
1. **Two unmount routes in `src/components/company-access/scoped-read-frame.tsx`**, both fixed by now:
   the same-address `router.replace` (fixed in `002c9df6`), and the 15 s observation window lapsing before renewal,
   which set `content:null` and drew the checking skeleton (fixed in `d3bbe73b7`). With both fixes, the period history
   unmount did not occur in 13 WebKit runs.
2. **"Reload current shift" race: a test issue, not the app.** `readiness-ui-browser.integration.ts:114–116` clicks the
   button (`window.location.reload()`, `src/components/shift-review-recovery.tsx:18`) and then waits for
   `[name="notes"]`, which the old document still has. In WebKit the reload sometimes starts after the read, so the test
   sees "Retained fictional draft". The failure shot is the old page, taken milliseconds later. The shift form has no
   `beforeunload` guard. Suggested fix in the test: wait for the reload (`load` event or the conflict alert detaching)
   before reading the field. It has been reported to the public-pages session and the lead.

Chromium page errors: 0 in every run. WebKit page errors: 0 in every run.

## How we work

- **Branch:** `claude-codex-collab-nevora` only. Pull before every slice; one finding (or one screen pass) per commit;
  push after each verified slice. Development and main only through the normal release, with Jose's approval.
- **Ownership:** the QA's Owner column. Claude does the UI; Codex does backend, data and the harness. When both own an
  item, Codex lands the server contract first and Claude builds the UI on it.
- **Design standard:** `nevora-design-os` (`.claude/skills/nevora-design-os/`; Codex via
  `.codex/skills/nevora-design-os/` and `AGENTS.md`). Every UI change gets its Impeccable audit before it's reported.
- **Decisions:** at each design choice, show Jose 2–3 options as screenshots on the real screen (fictional data), with
  a recommendation; Jose picks. Rules that already decide something (spacing scale, 44px, tokens) are applied and
  mentioned, not asked.
- **Safety:** fictional data and a throwaway local database only. No real mail, SMS, payments or AI provider.

## Density rules (to add to nevora-design-os in step 0.3)

1. Each fact appears once per screen.
2. A row is a title plus one line; a third line only for an exception (for example "Clocked in late").
3. The band holds the title and at most three figures; filters, notes and cards go below it.
4. One main action per card; other actions in a ⋯ menu.
5. Explanations show once (first visit, empty state or an info button), not on every visit.

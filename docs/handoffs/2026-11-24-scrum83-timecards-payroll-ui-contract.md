# SCRUM-83 Timecards and Payroll UI contracts

The bundled backend starts from Development `12263073083a2e5fc387a4728ed13ead7b346cc4`. That base includes the opt-in Clocker name picker and migration `0078_clocker_picker.sql`. This assembly adds `0079_timecard_missing_shift_disposition.sql` and integrates BL-20, BL-23, BL-17, and BL-14. SCRUM-83 records the exact tested commit and release hold. Claude owns the UI integration.

| Finding | Server response | Required UI behavior |
| --- | --- | --- |
| BL-20 · Published shift without time | Manager Timecards may include `source.shiftOutcomes` rows with `assignmentId`, `locationId`, local `date`, and `status` of `UNRESOLVED` or `APPROVED_CALLOUT`. An unresolved row adds `missing_shift_disposition`. Approve and Finalize respond HTTP 409 with `{status:"blocked",reason:"missing_shift_disposition"}`. | Keep the Timecard in review. Identify the date and location from the authorized payload. Direct the reviewer to the existing correction or approved published callout flow. Preserve the server state until refreshed. Treat an absent outcome list as empty for older snapshots. |
| BL-23 · Approved payroll protects finalized time | Reopen responds HTTP 409 with `{status:"blocked",reason:"payroll_approved"}` when an overlapping approved snapshot covers the employee. A pending payroll correction leaves the lock in place. | Explain the approved payroll lock and retain the finalized card. Recover an uncertain response using the original operation and existing receipt flow. |
| BL-17 · Independent approval | Payroll approval and manual publication respond HTTP 409 with `error:"PAYROLL_SELF_REVIEW"` for a financially interested actor. A historical self-approved revision returns HTTP 409 `error:"INDEPENDENT_PAYROLL_APPROVAL_REQUIRED"` on publication, or a publish job with `status:"FAILED"` and that error. | Ask for another authorized reviewer. Keep the current review or approved state. Use the normal review handoff for independence failures. Keep document availability tied to the server's publication state. |
| BL-14 · Export date boundary mismatch | Payroll export responds HTTP 400 with `{state:"invalid",reason:"PERIOD_BOUNDARY_MISMATCH"}` when SQL and application period bounds disagree. | Show the selected dates and business zone and direct the operator to reconcile the time records before reviewing a new export. Treat the refusal as deterministic and preserve previous receipts. |

Use the existing Company, Manager and employee authorities. For a known rejection, refresh current state and keep the review context visible. Preserve meaningful failure messages and exact operation IDs during uncertain outcomes. Keep the existing Spanish release sequence under SCRUM-91.

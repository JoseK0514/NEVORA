# Conversation context and accepted decisions

Jose began this project frustrated with an interface that did not feel intentional. He wants Nevora's mobile experience to meet the care of established workforce products such as Gusto, Homebase and ADP: deep empathy for nontechnical people, strong shared components, low cognitive load, useful breadth without crowded dashboards. Competitor research was requested early as a combination of useful patterns, not a brand/logo clone. Current accepted implementation is the reference for continuation; new research must serve a concrete unresolved decision, using connected tools or current primary sources when needed.

The broader eventual audience is Employee/Manager/Owner, but every task in THIS handoff is **mobile Owner only**. Desktop/Employee artifacts elsewhere in the original workspace are unrelated and intentionally excluded. “Owner page” became the Owner Home dashboard; do not interpret Owner profile as only the personal-account screen.

## Foundation to preserve

- Intentional, modern, clean, premium, calm and easy to understand. Jose repeatedly approved the improved direction and asks to maintain it.
- Accepted system font, teal/neutral palette, Nevora wordmark, Phosphor icon vocabulary, shared type/space/radius/control roles. Saved company branding is a deliberate feature; it is not permission for a new visual direction in each batch.
- Align controls and content deliberately. Consistent button geometry and44/48px control roles; long names or enlarged text should wrap/reflow instead of colliding or shrinking. New global tokens/components need a reusable need and a documented decision.
- One task per focused screen when the job warrants it; concise visible essentials, secondary facts/history behind meaningful disclosure. The root Home answers today's priorities rather than exposing every desktop feature at once.
- Preserve feature parity inventory and discoverability. A low-frequency tool can live under More/Settings/contextual Tools; it must remain reachable with a logical destination and accurate source/capability gate.
- Use shared source-backed data for counts and actions. Preserve exact person, date/week/period, location, filter/query, item, origin, scroll and focus through actions and Back/deep links.
- Distinguish sample/current/historical/unset/zero, source failure, blocked/known success/unknown result. Plain language rather than implementation jargon in the product. Screens should explain what happened and the useful next action.

## Repeated taste feedback already addressed

These are reasons behind existing components, not a new open request to restyle every screen:

- Date navigation arrows must align with the date scheduler; equal targets and balanced layout. Add shift/Add employee were refined from awkward bare icon buttons to coherent labeled task actions where space allows.
- Section counts previously looked like loose digits glued to headings. Use clear units/controlled spacing; avoid orphaned “On shift6” or bare numbers without hierarchy.
- Every native select uses a consistent inset chevron and reserved trailing text space. Jose repeatedly flagged arrows against the right border in Team status/role, shift fields, policies and coverage rules. Preserve native selection/accessibility.
- Native checkboxes/switches must look crafted and keep proper target, focus, keyboard and disabled behavior. Add/remove actions inside forms must have a clear hierarchy and breathing room; do not stack many equally prominent full-width controls without section structure.
- Warnings formerly used large beige/orange blocks and a calendar-X icon, which Jose called cheap/AI-looking. Accepted notices now use calm neutral surface, line, readable dark heading, muted copy and a restrained relevant icon; amber only for a real consequence. Draft is an informational status, not an emergency.
- Variable names/statuses need separate aligned content columns or intentional stacking. Disclosure arrows sit at the trailing edge; whole labels/values remain legible.
- Timecard period controls, count metadata, refresh, supporting text and empty-state action spacing needed a more deliberate hierarchy. Keep meaningful space before Clear filters and avoid disconnected “0 people / Recorded time” fragments.
- Upcoming staffing was refined into structured identity/time/context; Home now has a personal welcome, Add shortcuts and a clearer staffing summary. Do not add decorative metrics or gradients merely to look modern.
- Timecard-detail layout was marked an early layout by Jose; he explicitly moved on. Do not revive an unlimited redesign of accepted historical surfaces without new evidence or an approved requirement.

## Working rhythm Jose asked for

He wants extremely high UI/UX quality and once described zero error tolerance. Treat that as a demanding craft/verification bar; never promise literal perfection or call browser checks production certification. He authorized senior UI/UX review early and later a standing sequence: complete a phase, verify the whole phase, then move to the next. Keep one bounded batch active. A required failing check or unresolved material defect keeps it open. Avoid repeated routine “shall I continue?” prompts.

The established execution approach records a brief/source contract/plan/ledger and uses meaningful RED→GREEN regressions for defects, focused/neighboring browser/model checks, supported phone/text captures and a single fresh whole-slice final review where the available skill workflow requires it. Reviewer findings are regraded by actual user effect; material findings get one combined repair and final verification, minor findings stay visible. Do not repeatedly commission reviews or micro-polish accepted work without evidence. Platform-specific Cloud skill/delegation instructions still govern tool use.

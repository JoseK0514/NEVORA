## Boundaries and acceptance

Coverage proposals prepare an exact person, location, interval, position and lead requirement using canonical eligibility and the actor/workspace/source-bound repair review. Preparing or rejecting a proposal writes nothing. Opening and confirming revalidate current authority and facts. Draft assignment does not publish or enqueue notifications. A published assignment requires a separate, unchecked publication-and-notification consent before save, enforced again inside the canonical transaction. Duplicate/concurrent/stale confirmation creates at most one shift. Existing schedule workflows own execution and the saved receipt; the model has no write tool. Do not promise universal undo.

Attendance/payroll review accepts an explicit period of at most 31 days and English or Spanish. Canonical timecards supply recorded issues, review state and locations. Finalized cards are explicitly historical snapshots. Payroll supplies recorded run revisions, statuses and allowlisted exception categories. This lightweight review does not recalculate pay or verify current financial rules: readiness always remains unverified and the UI directs the Owner to the authoritative payroll review. Missing runs, disabled modules, incomplete coverage, superseded runs and unavailable sources cannot become ready. No private correction notes, monetary amounts, tax details, documents or bank data enter tool output. No mutation, tax advice or inferred punches.

Both workflows work without model inference through explicit forms; conversational tools return the same server-generated structured evidence. Links/actions come only from those server results. Existing original-authority, finite display lease, no-store and lifecycle retirement remain in force. No new model spend, background activity, external writes, integration or production deployment.

## Deliverable
A private host can invoke one fixed payroll/notifications-dispatch/notifications-reminders command under a time bound, record only sanitized invocation status in an owner-only directory, prevent same-host overlap and detect stale/failed heartbeats. A separate read-only queue health observation reports counts, expired leases and oldest due age using the canonical WORKER binding and explicit notification environment. Existing queues alone govern job retries/effects; never mark a job complete from a process receipt.

The runner requires explicit operations enablement, environment, source SHA, opaque scope ID and an existing private state directory. Commands are a closed allowlist; no shell or user-supplied executable/args. Source SHA in receipts is operator-declared, not cryptographic proof of deployment. One state directory per environment/company; receipts reject scope/source mismatches. No new DB grants/schema, HTTP endpoint, model calls, telemetry or provider activation. Native dispatch is absent from the allowlist.

One lock per command per private directory prevents overlapping local invocations; distributed business-key/lease fences remain canonical. SIGTERM/INT and watchdog deadlines terminate the owned child process group, await exit and record interruption/failure. SIGKILL/host crash leaves a stale lock and running receipt; do not automatically unlink a possibly live lock. Health must flag it, and the runbook requires pausing the scheduler and verifying local process custody before explicit removal. Atomic owner-only receipt writes preserve last success separately; disabled/failed/timeout/interrupted is never success. Child stdout/stderr, secrets, employee IDs and job payloads never enter the receipt.

Health thresholds and timer cadence are explicitly operator-selected, not an invented business SLA. Missing/malformed/future/stale receipt, ongoing over-budget invocation, failed result, expired leases, terminal queue failures and excessive due age are unhealthy. A successful idle invocation proves only the CLI exited0. Queue observations may not advance jobs or send anything; malformed/unavailable data fails closed. Pausing execution does not erase queue/health evidence. No actual external alert route is claimed until a named responder and approved existing sink are configured and an alarm/recovery event is observed.
